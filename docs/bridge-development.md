## 阶段 0 设计

- 一个命令进程只能装载一个账号，启动后禁止切换账号。目录预留 A1/A2/A3，不启动三账号服务。
- `AccountPaths` 管理全部 Cookie、设备、IM Token、限流、风控和扫码浏览器目录。
- 适配层仅在账号进程初始化时重定向上游缓存常量；Cookie 默认从比特浏览器“闲鱼”分组按账号昵称读取，优先读取已打开窗口的实时 Cookie；实时为空时先检查窗口状态，已打开则报错等待页面加载，不关闭用户窗口。已关闭时才读取详情接口同步快照，快照为空时临时无头打开读取。分组、昵称或 UID 校验失败时停止该账号，不自动选择其他浏览器身份。
- HTTP 使用 `trust_env=False`，WebSocket 显式 `proxy=None`，扫码 Chrome 使用 `--no-proxy-server`。
- 登录后在本地显示 Cookie 声明的 UID，人工输入相同 UID 确认绑定；服务端身份仍需探针联调核验。
- 监听保留全部推送结构，接收注册成功回包及 `/s/vulcan` 后才报告就绪。
- 采样只保存脱敏结构，字符串使用带随机盐的摘要；不猜测正常消息的源消息 ID 与源时间路径。
- 发送只用于明确指定的自有测试客户与已有会话，发出前持久化请求；发出后无明确回包记为 UNKNOWN，不重试。
- 飞书探针只绑定明确确认的本人私聊，保存 `message_id` 与 `parent_id`，不触发闲鱼发送。

## 排障与回归记录

- 上游 IM 请求 `mid`、客户端 UUID 有协议格式；替换为普通 UUID 时，实际历史查询不返回匹配回包。恢复上游生成函数后查询成功。已添加格式回归检查，正式适配层沿用同一生成方式。
- 飞书 SDK 正常断开时，必须先取消并回收 SDK 接收协程，再关闭 WebSocket；已用先失败再通过的回归测试覆盖。
- Windows 默认 GBK 下上游元数据测试读取失败，已显式指定 UTF-8。Unix 的 `st_mode == 0600` 不代表 Windows ACL，相关断言只在非 Windows 执行；当前运行目录另行实测设置 ACL。
- 所有账号缓存重定向仅在进程初始化时执行，不使用同进程切换账号；故障与未知发送不会自动重发。
- 样本字段名也可能包含 UID（例如 `squadId_<uid>`）；脱敏同时处理值和动态字段名，仅保留已知协议字段名。导出还会重新检查早期诊断记录，已补回归测试；私有诊断库仍按敏感数据保存在受限目录。
- 空会话的成功回包可能省略 `userMessageModels`，实测返回 `hasMore=0`、`degradeFailover=0`。只在这两个条件均成立时认定为空历史，其他未知结构仍报告缺口。初次运行产生的结构误报告警已修复；同账号补拉告警最多每分钟一条，所有具体缺口继续保存。
- 后来的实时消息只推进已见位置，不覆盖最后完整补拉检查点。数据库版本 2 自动新增 `sync_state.checkpoint`，升级不删除旧消息和任务。历史同步缺口只写本地 `sync_state` 和日志，不再推送到飞书；启动恢复会抑制旧版本遗留的历史告警队列。
- Windows PowerShell 5 脚本使用 UTF-8 BOM，已通过原生文件解析；只做语法验证，未执行计划任务注册。
- IM 注册 401/403 分别进入人工认证/风控暂停，避免把身份拒绝当作普通断线反复重连；发送接口出现对应拒绝时也暂停该账号。

## 运行接口与持久化

`python -m goofish_bridge run` 默认启动三个已绑定账号；`--accounts A1` 用于逐账号联调；`--test-customer-uid` 开启指定客户白名单和独立测试数据库；`--duration` 限时运行。

`stop` 写入退出请求，主进程停止子进程并保存结果；退出后未确认的 `DISPATCHING` 保守转为 `UNKNOWN`。`status` 只读正式业务库，不启动网络连接。飞书回调与账号子进程均通过队列提交事件，业务数据库仅由主进程写入。

SQLite 初次由 `Store` 自动建表，按 `PRAGMA user_version` 执行非破坏性升级；不兼容的更高版本直接拒绝。真实数据、账号凭据、日志和个人配置均由 `.gitignore` 排除。

日志记录账号状态与错误类型，不记录正文或认证包；`logs/bridge.log` 每文件 2 MB、保留 3 份轮转备份。所有敏感运行目录已设置当前用户和 SYSTEM 的 Windows ACL。

飞书展示层使用账号中文展示名（A1“北美草原狼”、A2“AI编程哥”、A3“影刀RPA专家”）；客户卡片隐藏账号 UID、客户 UID、会话 ID 和内部任务字段，回复回执只显示正文与最终状态。内部数据库仍保留完整路由字段。

卡片回复模式已接入：`feishu_cards` 持久化“账号 + 客户 + 会话”映射，首次消息创建卡片，后续消息引用原卡片另发提醒，原卡片仅在用户主动“查看更多／收起”时刷新。默认显示最近 4 条，展开显示最近 12 条。卡片输入框动作按卡片 `message_id` 定位发送目标；直接引用原卡片和客户新消息提醒均可固定路由。飞书应用还需启用 `card.action.trigger` 事件，真实卡片动作闭环待在手机端验收。

## 连续回复与成功静默（2026-09-19）
